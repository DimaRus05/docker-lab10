## Шаг 1. Исправил ошибки

1. В Compose был порт 445, хотя nginx слушает 443. Заменил на `127.0.0.1:443:443`, чтобы открывался `https://localhost`.
2. В Dockerfile для app2 запускался файл `app1.py`. Заменил его на `app2.py`.
3. Flask искал шаблон в папке `templates`, а общий файл лежит в `/storage`. Указал этот путь в обоих приложениях.
4. Приложения отвечали только на `/hello`. Добавил маршрут `/`, чтобы страница открывалась по основному адресу.
5. app2 не передавал своё имя в шаблон. Добавил `source_app='app2'`.
6. nginx обращался к приложениям на порту 81, app1 слушал 8080, а app2 слушал 80. Указал порт 8080 в обоих приложениях и в настройках nginx.
7. В nginx было `proxy_pass http://app`, но группа серверов называется `loadbalancer`. Исправил имя.
8. Сертификат и ключ не попадали в образ, а пути к ним были относительными. Теперь они создаются при сборке в `/etc/nginx/certs`.
9. Старый сертификат истёк в 2023 году и не подходил для localhost. Новый подходит для `localhost` и `127.0.0.1`.
10. Вместо `least_conn` настроил распределение запросов по очереди. Добавил общие счётчики, чтобы ответы чередовались при нескольких процессах nginx.
11. В HTML был закрывающий тег `</h1>` вместо открывающего. Исправил его.

Также убрал устаревшее поле `version`, выключил отладку Flask и добавил проверки готовности приложений. nginx запускается, когда оба приложения готовы. Общая папка с шаблоном доступна только для чтения. Запрос значка сайта обрабатывает сам nginx, чтобы не сбивать очередь приложений.

## Шаг 2. Запустил контейнеры

Проверил настройки, собрал и запустил стенд:

```bash
docker compose -p cloudtech-lab10 config --quiet
docker compose -p cloudtech-lab10 up --build -d
docker compose -p cloudtech-lab10 ps
docker compose -p cloudtech-lab10 exec -T nginx nginx -t
```

Все три контейнера запустились. У app1 и app2 статус `healthy`. Проверка настроек nginx прошла без ошибок.

## Шаг 3. Проверил результат

```bash
python3 check_lab.py
```

Все 13 проверок прошли. На 20 запросов к `https://localhost/` получил 20 ответов HTTP 200. Ответы строго чередовались: app1, app2, app1, app2. Каждое приложение ответило 10 раз. Сертификат прошёл проверку, соединение использовало TLS 1.3.
